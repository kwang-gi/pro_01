# PRD — 만남(가칭 Linker) MVP v2 (2026-07-06 인터뷰 2차 확정분)

> v1(0706_PRD_MVP_v1.md)에 사장님 10문 답변 + 추가 지시를 반영한 개정판. v1은 보관.

## ★ 최상위 설계 원칙 (사장님 지시 원문 기반)

1. **"이 모든 걸 다 만들어두고 관리자 페이지에서 선택할 수 있게 — 이게 핵심"**
   - 모든 정책(요금·비율·성사기준·예치방식 등)은 옵션으로 전부 구현
   - 관리자 페이지에서 **버튼/선택을 바꾸는 순간 즉시 적용** (재배포 없이)
   - 안 쓰는 옵션은 삭제가 아니라 **비활성(주석 아닌 설정값 off)** 상태로 보존
2. 블럭(톱니바퀴) 교체형 구조 유지 — 외부 연동은 [모의] Provider + 실블럭 자리
3. **클라이언트별 개별 제어**: 관리자 페이지 하나에서 각 클라이언트(PC/계정)마다 설정을 다르게 걸 수 있는 구조 (사장님이 과거 SQL 기반 유사 시스템 운영 경험 있음 — 그 방식 재현)
4. **버전 체크 자동 업데이트**: 웹/앱 로그인 직후 서버의 버전 확인 → 업데이트 자동 반영
5. **개인정보는 별도 분리 저장/운영** (메인 DB와 분리)

## 10문 답변 확정사항

| # | 항목 | 결정 |
|---|---|---|
| 1 | 성사비 | **주선비 2종 구조**: ①기본 주선비 7~10만 원 ②성공 사례비 50~80만 원 별도. 시작은 50~80, 이후 변경 가능 (관리자에서 금액 조정) |
| 2 | 예치금 방식 | **2가지 모드 모두 구현, 관리자 선택**: ①예치금 선입금 모드 ②예치금 없이 신청→입금 확인되면 연결 모드. 미사용 모드는 비활성 보존 |
| 3 | 여성 요금 | 여성 신청자는 극소수 전제(남 9 : 여 1 비율 가정). **①동일 요금 ②여성 우대, 둘 다 구현 → 관리자 선택**. 핵심은 회원 간 소개가 아니라 **주선자 경유** — 남성 주선자가 여초 직장이면 여성 회원 다수 유치, 여성 주선자는 여성 고객에게 연하남 등 소개 가능 |
| 4 | 분배 비율 | 기본 **주선자 7 : 플랫폼 3** (또는 8:2) — 관리자에서 일괄 변경 + **우수 주선자 추가 우대(+5% 등) 옵션** |
| 5 | 성사 기준 | **①3회 고정 ②신청자 선택형(3/5/7회/여행 등) 모두 구현 → 관리자가 모드 선택** |
| 6 | 만남 확인 | ③ 양측 버튼 + 주선자 크로스체크. **★신규 규칙: 소개받는 지인은 주선자가 수수료 받는 사실을 모르게 한다** (영업성 접근 최소화) — 지인·상대방 화면에 수수료 정보 절대 노출 금지 |
| 7 | 소개 방식 | ③ **둘 다**: 제안형(주선자→신청자) + 요청형(신청자 "이런 사람 원해요" 게시→주선자 응답) |
| 8 | 사진 | ② 텍스트 프로필만 (사진은 블럭 자리) |
| 9 | 관리자 | 처음엔 사장님 단독 콘솔 → 이후 단계적 자동화 |
| 10 | 배포 | ①사장님 PC → ②server01~03 자체 서버 → ③외부 서버 순 (단계 이동 가능하게) |

## 이에 따른 구현 항목 (다음 작업 목록)

1. **`settings` 테이블 + 관리자 설정 탭** — 모든 정책값(요금·비율·모드·성사기준)을 DB 설정으로: 바꾸면 즉시 반영
2. 주선비 2종 원장 반영 (기본 주선비 / 성공 사례비 분리)
3. 예치금 모드 A/B 스위치
4. 요청형 소개 게시판 (신청자 요청 → 주선자 응답)
5. 우수 주선자 우대(+5%) 로직
6. 성사 기준 모드 스위치 (고정/선택형)
7. 지인·상대 화면에서 수수료 정보 숨김 처리 검수
8. 버전 체크 API + 로그인 시 자동 업데이트 안내
9. 클라이언트별 개별 설정 오버라이드 (전역 설정 ← 클라이언트 설정 우선)
10. 개인정보 분리 저장 구조 (별도 테이블/파일 → 추후 별도 DB)

## 열린 질문 (남은 것)

- 서비스 이름 확정 (만남 / Linker / 기타) — 아직 답 없음
- 여성 우대 모드의 구체 값 (예치금만? 전액 면제?) — 자리만 만들고 값은 관리자에서
- 우수 주선자 기준 (건수? 성사율?) — 관리자 설정으로 열어둠
