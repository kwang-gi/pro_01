# 01 뉴스 수집

목적: 새로 나온 AI·자동화 소식을 매일 놓치지 않고 모아 한국어로 요약한다.

## 흐름 (한국 시각)

| 시각 | 무엇 | 누가 | 비용 |
|---|---|---|---|
| 06:20 | 뉴스 수집 (출처 11곳) | 깃허브 `automation.yml` 의 `news` 잡, 파이썬 `news_radar.py` | 0원 |
| 07:47 | 같은 수집의 예비 예약 (06:20 누락 대비, 재실행해도 안전) | 깃허브 | 0원 |
| 06:20 직후 | 현황판·옵시디언 폴더·멈춤 감시 | 깃허브 `report` 잡 | 0원 |
| 06:50 | 오늘 원자료가 없으면 수동 실행(`workflow_dispatch`)으로 먼저 수집, 그다음 요약 | "뉴스 v2" 루틴 | 구독 한도 |
| 요약 | 원자료 → 한국어 요약 | Haiku 5.5 | 구독 한도 |

실제 사정: 깃허브 예약(06:20, 07:47)은 10/9·10/10 실행 기록이 0건, 10/11에는 늦게(한국 시각 09:56, 10:55) 돌았습니다. 그래서 06:50 루틴이 "예약이 안 돌았으면 수동 실행"을 자기 절차에 넣었고, 이 방식으로 10/10~10/12 아침 요약이 06:5x 에 만들어졌습니다.

## 입력과 출력 경로

| 구분 | 경로 |
|---|---|
| 설정 | 저장소 `automation/config/news_sources.json` (출처·키워드는 여기만 고친다) |
| 저장소 원자료 | `data/news/YYYY-MM-DD.md` (맨 아래 "수집 상태" 표에 출처별 성공/실패) |
| 프로젝트 원자료 사본 | `/mnt/project-files/news/raw/YYYY-MM-DD.md` |
| 요약 | `/mnt/project-files/news/YYYY-MM-DD-레이더요약.md` |
| 드라이브 | `지식센터/뉴스` 폴더. 같은 이름 파일이 있으면 새로 만들지 않고 update |

## 요약 양식 (템플릿)

````
# AI·자동화 뉴스 (레이더 요약) — YYYY-MM-DD

## 오늘의 핵심 3줄
1. <주제 + 우리에게 쓸모>
2. ...
3. ...

---

### <항목 제목>
요약: <2~3문장. 원자료에 있는 내용만>
실장님 업무에 쓸모: <한 줄>
소스: <원본 URL>

(5~7개 항목)

---

## 제외한 항목
- <제목>: <제외 이유 한 줄. 중복·업무 무관·본문 미확인>

---

수집=GitHub Actions 파이썬(0원, N/11 소스 성공) · 요약=Haiku 5.5
````

규칙: 원자료에 없는 내용은 쓰지 않는다. 본문을 못 읽고 제목만 본 항목은 "본문 미확인"이라고 적는다. 어제와 같은 건은 "제외한 항목"에 중복으로 남긴다.

## 검증 방법

1. 원자료 맨 아래 "수집 상태" 표에서 출처 성공 수(정상은 11/11)를 확인한다.
2. 요약의 소스 URL을 전부 원자료에서 찾아 대조한다. 없는 링크가 있으면 그 항목을 뺀다.
3. 저장 후 파일을 다시 읽어 핵심 3줄이 있는지 확인한다. 드라이브는 폴더 목록으로 확인한다.
4. 현황판 `data/status.json` 의 `stale: false`, `problems: []` 확인.

## 고장 시 대처

| 증상 | 대처 |
|---|---|
| 오늘 원자료 없음 | 깃허브 `automation` 워크플로를 수동 실행해 11/11 확보 후 요약 (10/9 08:08 점검이, 10/10 아침 뉴스 스레드가 이렇게 복구) |
| 출처 일부만 수집됨 (10/8에는 클로드 쪽 네트워크 제한으로 3/11) | 요약 파일 이름에 `부분수집판`을 붙여 두고, 11/11 원자료가 생기면 다시 만들어 교체 (10/10에 같은 방식으로 처리) |
| 이틀 넘게 안 쌓임 | 멈춤 감시가 "자동화 멈춤 알림" 이슈를 열어 이메일·앱으로 알림. 정상이 되면 자동으로 닫힘 |
| 같은 날 수집을 두 번 돌림 | 앞서 모은 소식이 지워지지 않도록 고쳐져 있음(10/9 PR #5). 건수가 줄었으면 이상 신호 |
