# 05 보고 형식

원칙: 실장님은 길게 읽지 않는다. 채팅은 짧게, 자세한 것은 문서 첨부.

## 스레드 보고 (완료 시 한 번만)

| 항목 | 규칙 |
|---|---|
| 줄 수 | 최대 3줄. 중간 진행 보고는 하지 않는다 |
| 내용 | 확인된 결과만. 무엇을 했고, 결과가 어디 있고, 검증한 것 |
| 첨부 | 결과 문서를 파일로 첨부(절대 경로). 길면 문서에 쓰고 채팅엔 요약 |
| 분업 | 마지막에 한 줄: `분업: 판단·검수=Opus · 구현=Sonnet · 요약=Haiku · 수집=파이썬(0원)` |
| 미확인 | 확인 못 한 것은 "미확인"이라고 한 줄로 적는다 |
| 어투 | 한국어, 쉬운 말 |

### 요청 꼬리 금지

아래 같은 문구는 보고에 쓰지 않는다. 사전 승인 범위의 일은 이미 끝낸 상태로 보고한다.

- "~해 주세요", "눌러 주세요", "승인해 주세요", "병합 봐주세요"
- "추천 / 해야 할 일 / 결정할 일" 꼬리, 번호 선택지(★)
- 예외 3가지(결제, 복구 불가 삭제, 비밀값 생성·추측)는 진행하지 않고 "보류: 사유" 한 줄만 쓴다.

### 예시 (3줄)

````
1. 뉴스 요약 완료: 출처 11/11, 항목 7개, 링크 전부 원자료와 대조함.
2. 파일: /mnt/project-files/news/YYYY-MM-DD-레이더요약.md (첨부), 드라이브 뉴스 폴더 저장 확인.
3. 분업: 판단·검수=Opus · 요약=Haiku · 수집=파이썬(0원)
````

## 문서 끝 분업표 (모든 결과 문서 맨 아래)

짧은 한 줄 형식(요약·뉴스류):

````
수집=GitHub Actions 파이썬(0원) · 요약=Haiku 5.5 · 검수=Opus 5.5
````

표 형식(구축·점검류):

````
## 분업
| 모델 | 한 일 |
|---|---|
| Opus 5.5 | 대상 고르기·나누기, 결과 검수 |
| Sonnet 5.5 | 구현·문서 작성·시험 |
| Haiku 5.5 | 대량 요약·저장 |
| 파이썬 | 수집·집계·감시 (0원) |
````

호출하지 않은 모델은 "이번에는 일이 작아 호출하지 않음"으로 적는다. 판정 기준은 `plans/모델분업-기준표.md`.

## 공유 폴더에 쓴 뒤

파일을 다시 읽어 내용과 줄 수를 확인하고, 드라이브는 폴더 목록으로 확인한 뒤에 "저장됨"이라고 보고한다.
