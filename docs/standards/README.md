## 공통 원칙 5줄

1. 모델 분업: 파이썬 → Haiku → Sonnet → Opus 순으로 싼 쪽부터 쓰고, 올리는 조건은 원본 기준표를 따릅니다. 기준표 원본: 프로젝트 라이브러리 `plans/모델분업-기준표.md` (여기에 복사하지 않음).
2. 0원 우선: 기계가 할 수 있는 일은 파이썬(깃허브 무료 실행)이 하고, 모델은 판단이 필요한 곳에만 씁니다.
3. 사전 승인 범위: 병합·커밋·파일 이동·폴더 생성·루틴 생성·저장소 변경은 묻지 않고 진행합니다. 예외는 결제, 복구 불가능한 삭제, 비밀값 생성·추측·우회 세 가지뿐입니다.
4. 보고는 확인된 결과만 씁니다. 확인 못 한 것은 "미확인"이라고 적고, 사용자에게 "이거 해라·눌러라·승인해라"를 쓰지 않습니다.
5. 공유 폴더(`/mnt/project-files`, 드라이브)에 쓴 뒤에는 반드시 다시 읽어 저장됐는지 확인합니다.

## 모델 분업 기준표 요약 (3줄)

- 판정 순서: 규칙으로 되나(파이썬 0원) → 같은 양식 대량 반복(Haiku) → 정해진 절차 구현·정리(Sonnet) → 나머지 중 되돌릴 수 없는 결정·새 설계·모순 판단·반복 실패 분석·최종 검수(Opus).
- Opus는 기획·분해·검수만, 긴 본문 작성과 단순 요약은 맡기지 않습니다.
- Haiku 결과가 기계 채점에서 2번 떨어지면 Sonnet으로, Sonnet이 2번 실패하면 Opus가 원인을 봅니다.
