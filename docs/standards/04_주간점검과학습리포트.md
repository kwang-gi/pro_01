# 04 주간 점검(금 08:50)과 학습 리포트(금 09:12)

## A. 주간 자동화 점검 — 금요일 08:50

목적: 한 주 동안 자동화가 실제로 돌았는지 숫자로 확인하고, 가장 큰 막힘 하나를 푼다.
저장: `/mnt/project-files/reports/주간점검-YYYY-MM-DD.md` (+ 드라이브 `학습` 폴더)

### 확인 항목

| 항목 | 어디서 | 정상 기준 |
|---|---|---|
| 깃허브 `automation` 최근 7일 실행 | 실행 기록 (전체·예약·수동·PR 검증 구분) | 실패 0건. 예약 0회면 원인과 복구를 적는다 |
| 뉴스 원자료 | `data/news` 최근 7일 | **합격: 7일 연속 매일 저장**, 출처 11/11 |
| 영상 스크립트 | `data/scripts/index.csv` | **합격: 첫 30개 수집** (목표 300) |
| jev 노트·하이쿠 비용 | `data/notes`, `_run_*.json` | 통과율·비용 기록 (입력 없으면 "측정 불가") |

### 양식 (템플릿)

````
# 주간 자동화 점검 — YYYY-MM-DD (금)
## 1. GitHub Actions 'automation' 최근 7일   (표: 구분·횟수·결과)
## 2. 쌓인 양                                 (표: 항목·값·목표 대비)
## 3. 이번 주에 만든 것                        (고른 이유 → 한 일 → 결과 → 처리)
## 4. 분업                                    (표: 누가·한 일)
````

### 합격 여부 판정

- 10/9 첫 점검 결과: 실행 14회 전부 성공, 예약 실행 0회, 뉴스 164건(출처 11/11), 스크립트 0/300. 유튜브가 깃허브 서버를 막아(접속 방식 7가지 모두 차단) 스크립트는 PC 수집이 필요하다고 확정.
- 합격 기준 두 개가 모두 충족될 때만 "합격"이라고 쓴다. 하나라도 아니면 어느 쪽이 얼마나 부족한지 숫자로 적는다.

## B. 주간 학습 리포트 — 금요일 09:12

목적: 실장님과 Claude가 새 기술 사용법을 함께 익히는 쉬운 말 리포트.
담당: Haiku 5.5 작성, Opus 5.5 검수. 저장: `reports/주간학습-YYYY-MM-DD.md` + 드라이브 `학습` 폴더.

### 양식 (템플릿, 순서 고정)

````
# 주간 학습 리포트 (YYYY-MM-DD)
- 기간 / 자료 범위(없는 날짜는 있는 그대로) / 대상: 실장님 / 상태
## 이번 주 핵심 3줄
## 쉬운 용어 풀이          (토큰·에이전트 같은 말 5~6개, 한 줄씩)
## TOP 5 소식              (각각: 쉬운 말 / 왜 실장님께 중요한가 / 링크)
## 우리 작업에 바로 적용할 것 3개   (각각: 어떻게 / 근거)
## 다른 사람들은 이렇게 쓰고 있다   (사례 3개, 링크)
분업: 자료 수집=파이썬(0원) · 리포트 작성=Haiku 5.5 · 검수=Opus 5.5
````

### 검증

1. 리포트의 링크를 전부 그 주 원자료(`news/raw`)와 하나씩 대조한다 (10/9 첫 회: 9개 모두 있음).
2. 본문을 못 열고 제목만 본 사례는 "제목 기준"이라고 적는다. 단일 출처 주장은 "(단일 출처)".
3. 저장 후 파일을 다시 읽고, 드라이브 폴더 목록에서 파일을 확인한다.
