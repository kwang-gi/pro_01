> 사장님 지시: 자문스킬로 방향 교차확인 + 별도 에이전트로 검증 계획 수립.
> 원칙: **작성자와 검증자 분리** (만든 에이전트가 스스로 채점 금지), 검증은 사용자가 실제 쓰는 방식 그대로 재현.

| ③ 외부 AI 교차 | codex(GPT-5.5) → agy(Gemini 3.1 Pro) | 아키텍처·설계 결함 (구현 전 방향 검증) | 단계 착수 전 / 큰 결정 시 |

## 2. 외부 자문 결과 (0706)

### codex 1차 (완료) — "방향 타당, 단 3가지 지금 잡아라"
1. **돈 관련 설정값은 사용 시점 snapshot 저장** — 관리자가 나중에 값 바꿔도 진행 중인 건은 불변 → ★구현 에이전트에 반영 지시함
2. **잔고 중심이 아닌 원장(ledger, append-only) 중심** — 금액 float 금지, 정수 원 단위 → ★반영 지시함
3. **비밀번호 해시는 지인 테스트 단계부터** — 사장님 결정(보안 전부 공란)과 충돌 → **사장님 판단 대기**
- 기타: SQLite WAL+트랜잭션(반영 지시함), 설정 변경 이력 테이블(반영 지시함), Provider는 설정으로 선택(이미 settings 설계에 부합), 설정 DB화는 운영값만·상태머신은 코드 고정(이미 그렇게 설계됨)

### agy 2차 확증 (완료) — "진단 대체로 동의, 일부 과함 + 빠진 위험 있음"
- **동의(양쪽 일치 → 확정 적용)**: 설정값 snapshot / 정수 금액 / WAL+트랜잭션 / 비밀번호 해시 권고 / 설정·코드 분리
- **MVP엔 과함(가볍게 타협)**: 전면 audit log → settings_history만 최소로 / 역분개 → 관리자 '조정' 항목 수기 추가 수준 / 완전 append-only 원장 → 현행 잔고+이력 수준 유지 후 확장
- **새 위험 지적 (반영)**:
  1. ★서버리스(Vercel류) 배포 시 SQLite 파일 증발 → 외부 배포는 VPS/볼륨 컨테이너 필수 (PRD 11장에 경고 추가)
  2. dev HMR 시 DB 커넥션 누수 → globalThis 싱글톤 확인 (구현 에이전트에 지시함)
  3. 백업 전략 부재 → DB 파일 주기 백업 스크립트, server01~03 이전 시 필수 (공란 등록)
  4. 매 요청 직조회는 트래픽 증가 시 짧은 TTL 캐시 고려 (지금 규모는 문제 없음 — 공란)
