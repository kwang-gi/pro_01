## 2. MVP 범위 (포함)

1. 역할 4종: 신청자(남/여), 주선자, 관리자 — mock 로그인
2. 가입·인증: 여성 문자[모의], 남성·주선자 등기[모의→관리자 승인]
3. 예치금 5+주선비 1=6 선입금 [모의 입금 신고→관리자 확인]
4. 주선자 지인 등록 (최소 정보) + 지인 동의 [모의 알림톡]
5. 성비 룰: 남자 주선자는 여자만 등록 가능
6. 소개 제안→수락(주선비 차감)→만남 1~3회 기록→성사→잔금 5→원장 기록·주선자 분배(기본 50%)
7. 만남 확정 전 금지조항·현실자각 경고 팝업 (김비서 멘트)
8. 무관용 신고→관리자 몰수(가해자+주선자 연대)+자동 전체 공지+피해자 환불
9. 동일 지인 쿨타임 (월 3회)
10. 주선자 성사율 표시, 환불 정책(매칭 전 즉시/후 유예)
11. 관리자 대시보드 (승인·입금확인·몰수·공지·목록)

## 3. 제외 (이번 MVP 아님)

- 실제 PG/가상계좌, 실제 등기 발송, 실제 알림톡 (블럭 자리만)
- 관문 홈페이지(소개·다운로드·버전관리)
- Tauri 설치형 클라이언트, 유령DB·다중서버 등 보안 요새 아키텍처 (설계 문서로만 유지)
- 김비서 애니메이션 (텍스트 팝업으로 대체)
- 채팅, 사진 업로드, 등급제 자동화(성사율 표시까지만)

## 4. 기술 스택

- Next.js(App Router) + TypeScript + SQLite(better-sqlite3) — 전부 로컬, 외부 의존 0
- 모듈: src/modules/{payment, verification, notify, matching, settlement, report, notice}
- 각 외부 연동 모듈 = Provider 인터페이스 + Mock 구현 + 실제 블럭 stub 자리
- 위치: `linker-app/`
