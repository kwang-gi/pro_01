# 만남 (가칭 Linker) — 지인 소개 매칭 MVP

지인 소개 기반 매칭 웹앱 MVP. Next.js(App Router) + TypeScript + SQLite(better-sqlite3)로
전부 로컬에서 동작하며, 외부 서비스(PG/문자/알림톡 등)는 전부 **[모의] Mock Provider**로
대체되어 있습니다. 실제 서비스 연동 시 각 모듈 폴더의 Provider만 교체하면 됩니다.

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:3000 접속. 최초 실행 시 `data/linker.db` SQLite 파일이 자동 생성되고
시드 데이터가 주입됩니다 (파일이 이미 있으면 재시드하지 않음. 초기화하려면 `data/` 폴더 삭제 후 재실행).

빌드: `npm run build` / 배포용 실행: `npm run start`

## 화면 구성

- `/`, `/login`, `/signup` — 랜딩/로그인/회원가입(역할 선택)
- `/dashboard` — 신청자용: 잔고, 받은 제안 수락/거절, 입금 신고
- `/meetings/[제안ID]` — 만남 확정 전 경고 팝업 확인 → 만남 1~3회 기록 → 신고하기
- `/broker/acquaintances` — 주선자: 지인 등록(성비 룰 적용) + 지인 동의 처리[모의]
- `/broker/propose` — 주선자: 동의 완료된 지인을 신청자에게 소개 제안
- `/broker/settlement` — 주선자: 내 정산(성사비 분배) 현황
- `/notices` — 전체 공지 게시판 (신고 확정 시 자동 공지 포함)
- `/admin` — 관리자 콘솔: 가입 승인(등기[모의]), 입금 확인, 신고/몰수 처리, 공지 작성,
  주선자 성사율, 정산 지급 처리

## 블럭(모듈) 구조 — `src/modules/`

각 모듈은 서로 직접 import하지 않고, 외부 연동이 필요한 부분은 `xxxProvider` 인터페이스 +
`MockXxxProvider` 구현체로 분리했습니다. 실제 서비스 연동 시 아래 표의 "교체 지점"만 고치면
나머지 코드(API 라우트, 화면)는 수정할 필요가 없습니다.

| 모듈 | 역할 | 교체 지점 |
|---|---|---|
| `payment/` | 예치금5+주선비1 최초 입금, 잔금5 입금 — 현재는 "입금 신고→관리자 확인" | `TossProvider.stub.ts` 구현 후 `index.ts`의 export 교체 |
| `verification/` | 여성=문자인증[모의 즉시활성], 남성·주선자=등기인증[모의 승인대기] | `MockSmsVerification`/`MockRegisteredMail`을 실제 SMS/등기 API로 교체 |
| `notify/` | 지인 동의 알림(카카오 알림톡 대신 화면 버튼으로 동의 처리) | `MockAlimtalk`을 실제 알림톡 API 연동 클래스로 교체 |
| `matching/` | 소개 제안/수락/만남기록(1~3회)/성사 판정, 성비 룰, 월 3회 쿨타임 (핵심 도메인, 모의 아님) | 정책 변경 시 `rules.ts` 상수만 수정 |
| `settlement/` | 예치금/주선비/성사비 원장(ledger), 몰수, 주선자 정산 대기 | 회계 시스템 연동 시 내부 구현만 교체 |
| `report/` | 무관용 신고 접수 (폭력/포교/사업/돈 4대 조항), 확정 시 몰수+공지+환불 일괄 처리 | 없음 (외부 연동 없는 순수 도메인 로직) |
| `notice/` | 전체 공지 게시판 | 없음 |

각 모듈 폴더 안의 `README.md`에 좀 더 자세한 설명이 있습니다.

## 핵심 도메인 규칙 요약

- 최초 입금: 예치금 5 + 주선비 1 = 6 [모의 입금 신고 → 관리자 승인 시 잔고 반영]
- 소개 제안 수락 시 주선비 1 차감 → 만남 1~3회 기록(양측 확인) → 3회 완료 시 성사
- 성사 시 잔금 5 입금 신고 자동 생성[모의] + 총 성사비 10 원장 기록, 주선자 분배(기본 50%, `broker_rate` 필드로 약정 비율 조정 가능)
- 만남 확정 직전 금지조항 경고 팝업 필수 확인 (돈/종교/사업/폭언 → 예치금 전액 몰수 경고)
- 신고 확정 시: 가해자 예치금 전액 몰수 + 해당 건 주선자 연대 몰수 + 자동 전체 공지 생성 + 신고자(피해자) 예치금 즉시 환불
- 동일 지인 월 3회 초과 소개 차단(쿨타임)
- 환불: 매칭 이력 없으면 즉시 환불, 있으면 "환불 대기(유예)" 후 관리자 처리

## 기술 스택

- Next.js 16 (App Router, Route Handlers 기반 API) + TypeScript + Tailwind CSS
- DB: SQLite (`better-sqlite3`), 파일 위치 `data/linker.db` (전부 로컬, 외부 서비스 없음)
- 인증: 세션 쿠키 기반 mock auth (아이디+비밀번호, 평문 저장 — **데모 전용, 실서비스 전환 시 반드시 해시 처리 필요**)

## 알려진 제한 사항 / 미구현

- 비밀번호는 평문 저장(데모 편의). 실서비스 전환 전 bcrypt 등으로 해시 필요.
- 주선자에게는 별도 "예치금" 계좌 개념이 없어, 신고 연대 몰수 시 주선자 몰수액이 0으로 처리되는 경우가 있음(주선자 보증금 정책이 확정되면 `ledger_accounts`에 주선자용 보증금 필드 추가 필요).
- 알림/문자/등기/PG 전부 [모의] 처리이며 실제 발송/결제는 이루어지지 않음.
- 신고 대상(`accused_id`) 선택 UI가 "이 제안의 신청자"로 단순화되어 있어, 실제로는 지인 본인을 특정할 계정이 없는 구조적 한계가 있음(지인은 users 테이블이 아닌 acquaintances 테이블에 별도 저장되는 프로필이라 로그인 계정이 없음).
